This project folder (Agentic Inference Optimizer) is a Python starter framework for benchmarking, diagnosing, and safely tuning LLM inference on an NVIDIA GPU host (targeted at vLLM on Ubuntu/H100).

What It Includes

  
Benchmarking (benchmark/):
  
  

  
Async OpenAI-compatible streaming client (engine_adapter.py) and bounded-concurrency runner with warmup and repeated trials (runner.py, run_cli.py).

  
Computes TTFT, TPOT (using server-provided token usage rather than SSE chunk counts), request latency percentiles, output tokens/sec, and error rate (metrics.py).

  
GPU inspection via nvidia-smi (gpu_info.py).

  

  
GPU Profiling (profiling/):
  
  

  
nvidia-smi telemetry collection (gpu_telemetry.py) and wrappers for NVIDIA Nsight Systems (nsys_capture.py) and Nsight Compute (ncu_capture.py).

  

  
Diagnosis & Optimization (agents/, optimizer/, orchestration/):
  
  

  
Evidence-labelled heuristic bottleneck diagnosis (diagnosis_agent.py).

  
Pydantic allow-list for safe candidate vLLM settings (constraints.py), candidate search (search.py), comparison (compare.py), and orchestration (controller.py).

  

  
Control Plane API & Persistence (api/, configs/):
  
  

  
FastAPI service (main.py) exposing /health, /v1/system/gpus, and /v1/benchmarks endpoints with atomic local JSON result persistence.

  

  
Unit Tests (tests/):
  
  

  
Pytest suites covering constraints, diagnosis, and metrics (test_constraints.py, test_diagnosis.py, test_metrics.py).

  

  

For setup, CLI usage, and metric caveats, see README.md.

DEBUG THE CODE

I audited the codebase and fixed several bugs:

Fixes Applied

  
Background task GC risk, path traversal, and event-loop blocking in api/main.py:
  
  

  
Stored asyncio.create_task(...) references in background_tasks with a done callback so long-running benchmark tasks cannot be garbage-collected mid-execution.

  
Validated run_id as a UUID in get_benchmark (api/main.py) to prevent path traversal outside results_dir.

  
Offloaded synchronous snapshot() (nvidia-smi subprocess) to asyncio.to_thread(snapshot) in gpu_status.

  

  
Event-loop blocking in orchestration in orchestration/controller.py:
  
  

  
Offloaded snapshot() to asyncio.to_thread(snapshot) inside execute.

  

  
Misleading 0.0 throughput when usage metadata is missing in benchmark/metrics.py:
  
  

  
Set completion_tokens and output_tokens_per_second to None when token_usage_available is False, matching the contract in README.md.

  

  
Threshold boundary gap in agents/diagnosis_agent.py:
  
  

  
Changed tpot < 0.08 to tpot <= 0.08 so tpot == 0.08 with ttft > 2.0 is not skipped.

WHAT NEXT HOW TO SEE THE RESULTS

Right now results/ is empty because no benchmark has been run yet. Here is how to run one and view the results:

1. Configure .env

Copy .env.example to .env and point it at a running vLLM (or OpenAI-compatible) server:

bash
cp .env.example .env

Edit .env to set VLLM_BASE_URL, VLLM_MODEL, and VLLM_API_KEY.
(Note: Since you're on a MacBook Air without an NVIDIA GPU, nvidia-smi telemetry will simply record an error string inside the diagnosis block rather than failing the benchmark, as long as VLLM_BASE_URL points to a reachable inference server.)

2. Run a Benchmark & See Results
Option A: CLI (benchmark/run_cli.py)

Runs the benchmark and prints run_id, aggregate metrics, and diagnosis directly to your terminal:

bash
set -a && source .env && set +a
.venv/bin/python -m benchmark.run_cli --requests 40 --concurrency 4 --input-tokens 256 --output-tokens 128 --warmup 4 --trials 3
Option B: FastAPI Control Plane (api/main.py)

Start the API server:

bash
set -a && source .env && set +a
.venv/bin/uvicorn api.main:app --host 127.0.0.1 --port 8080

Then either open http://127.0.0.1:8080/docs in your browser (interactive Swagger UI) or use curl:

bash
# 1. Start a run (returns {"run_id": "...", "status": "queued"})
curl -s http://127.0.0.1:8080/v1/benchmarks \
  -H 'content-type: application/json' \
  -d '{"requests":40,"concurrency":4,"input_tokens":256,"output_tokens":128,"warmup":4,"trials":2}'
# 2. List all runs in memory
curl -s http://127.0.0.1:8080/v1/benchmarks
# 3. View full results for a run_id
curl -s http://127.0.0.1:8080/v1/benchmarks/<RUN_ID>
3. Saved Result Files on Disk

Every completed run (whether from the CLI or API) is saved by orchestration/controller.py in results/:


  
results/<run_id>.json — full output (workload, warmup, per-trial stats, aggregate percentiles/throughput, raw per-request samples, and heuristic diagnosis).

  
results/runs.jsonl — one-line-per-run summary log (run_id + aggregate) for comparing runs over time.
